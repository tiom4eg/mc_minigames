# Potato Minigames contributor rules

- Keep the root `README.md` about the plugin: requirements, installation, shared systems, commands, build and a short game index. Put a game's rules, modes, controls, configs and operator instructions in the `README.md` beside its sources under `src/main/java/me/petr1furious/potatominigames/games/`. Update the relevant README with behavior changes; keep temporary logs and playtest evidence out of source control.
- Keep world archives, maps, textures and other deploy-only static files on the deployment, not in Git or in the plugin JAR. Install map payloads under the plugin data directory and retain upstream licenses and attribution with them. Keep code, small defaults and translations versioned. Never commit production configs, credentials, player data, private deployment scripts, or output from builds or playtests.
- Put automated checks in `src/checks/java`, opt-in MockBukkit checks in `src/checks/mock`, native fixtures in `src/checks/native`, and reproducible helper scripts in `src/checks/tools`. No new top-level test/tool trees. Checks should test player-visible behavior or real runtime contracts; keep them isolated and deterministic. Public `./gradlew build` must work without deployed assets.
- Java 25, Paper/AdvancedSlimePaper. Follow the existing package, configuration and session lifecycles. Keep Bukkit calls on the server thread unless the API says otherwise; release tasks, worlds and player state on end and failed start. Preserve existing IDs and saved data or supply a migration. Reuse shared implementations for shared behavior.
- Format code mechanically with `bash src/checks/tools/format-code.sh` (or `--check` to only verify). The script pins google-java-format AOSP for Java, ktfmt Kotlin style for Gradle Kotlin DSL, Black for Python, and Prettier for Groovy fixtures. Preserve the generated Gradle wrapper. Keep the formatter cache under `.tools/` or outside the checkout. Do not combine broad reformatting with unrelated logic changes.
- Follow `i18n/`: every built-in player-facing message, command help/error, menu, title, item name/lore and HUD label uses `I18n.tr` and ships matching UTF-8 `en`/`ru` keys in the same change. Declare new domains in `i18n/locales/catalogs.txt`. Use flat quoted YAML, full sentences, balanced MiniMessage tags and contiguous matching `<arg:N>` indices from zero. Pass user text, numbers and rich components as arguments; never interpolate them into MiniMessage or translate stable internal IDs. Use native translation keys for vanilla labels. Render inventory titles and fresh item metadata per viewer, never a shared item template. Pass untranslated components to `SidebarService`; preserve `I18n.exception` messages with `I18n.message`.
- Run the affected Gradle check tasks and `./gradlew checkI18n` for localization changes. Use a disposable native Paper/ASP instance for changes to inventories, dialogs, world handling or other server behavior a JVM check cannot see. Keep live deploy and restart manual and outside this repository.
